# 情境指南：兩邊不一樣時會怎樣

來源改了、產物被 AI 改了、連結壞了……每種狀況 `status` 會顯示什麼、`apply` 會做什麼，這一章用對照表列出。不確定時先跑唯讀的 `agsy status`，把輸出對回這裡。

## 一、兩條通則

1. **apply 以來源為準。** 重建讓產物回到來源的現況；產物端的改動會被覆蓋或刪除，但一定先列出、先確認。
2. **要保留產物端的改動，只有一條路：搬進來源。** 沒有「寫回」指令；status 會告訴你每一筆該搬去哪。

## 二、agsy 怎麼知道是誰改的

每次 `apply`，manifest 記下兩種指紋：

```
                     ┌── 來源的指紋
 建置當下 ───────────┤
                     └── 每個產物的指紋

 之後任何時候：
   現在的來源 vs 來源指紋   不同 → 來源改了   （清單 A，apply 會同步）
   現在的產物 vs 產物指紋   不同 → 產物端改了 （清單 B，apply 會捨棄）
```

## 三、主矩陣：來源端 × 產物端

「產物端」是你或 AI 工具透過連結碰到的東西，也就是 `.agsy/` 裡的檔案。

| # | 來源端 | 產物端 | status 顯示 | apply |
|---|--------|--------|------------|-------|
| 1 | 沒變 | 沒變 | 無落差 | 重建，內容相同 |
| 2 | 改了 | 沒變 | 清單 A：更新 | 重建，所有工具拿到新內容 |
| 3 | 沒變 | 改了 | 清單 B：修改，附保留指引 | 列出，詢問「捨棄並重建？」 |
| 4 | 改了 | 改了 | 清單 A ＋ 清單 B | 同上；同意後以來源為準 |
| 5 | 新增檔案 | — | 清單 A：新增 | 收進產物 |
| 6 | — | 新增檔案 | 清單 B：未追蹤，附「搬進某個來源」 | 列出，確認後刪除 |
| 7 | 刪除檔案 | 沒變 | 清單 A：移除 ⚠（轉換產物一併消失） | 該項目從所有工具消失 |
| 8 | 整個來源路徑不存在 | 任意 | ⚠ 來源路徑不存在 | ✘ 拒絕執行 |
| 9 | 沒變 | 產物副本被刪 | 產物缺失 | 重建 |
| 10 | — | 轉換產物被改（AGENTS.md、轉接頭、workflow 的 skill） | 清單 B：修改，指引指向來源檔 | 詢問後重新產生 |

## 四、保留產物端改動的做法

未追蹤檔通常是 AI 工具透過連結新增的（例如替你寫的新規則）。想保留：

```sh
# 從產物搬進某個來源的對應子資料夾
mv .agsy/rules/new-rule.md ~/all-ai-lib/rules/
agsy apply
```

被修改的已追蹤檔：把變更合併進來源檔。被改的轉換產物：改它的來源。

| 被改的檔案 | 該改的是 |
|-----------|---------|
| `AGENTS.md`（根目錄或 `.agsy/` 裡） | 對應的來源 rule；每段開頭有 `<!-- agsy: rules/… -->` 標記 |
| `workflows/<名稱>.md`（轉接頭） | 來源的 workflow 檔 |
| `skills/<名稱>/SKILL.md`（workflow 變成的 skill） | 來源的 workflow 檔 |

什麼都不保留、直接 apply：確認清單列出每筆改動，同意後捨棄。

## 五、連結出狀況

這是「通道」的問題，不是內容差異：

| 情境 | status 顯示 | 怎麼發生 | 處理 |
|------|------------|---------|------|
| 連結不見 | ✘ 連結遺失 | 被手動刪除，或還沒 apply 過 | `agsy apply` |
| 連結指向別處 | ✘ 指向 …,不是目前設定的目標 | `build.out` 改了，或連結被動過 | `agsy apply` |
| 連結已斷 | ✘ 目標不存在 | `.agsy/` 被刪，或專案搬移（Windows 的 junction 記絕對路徑） | `agsy apply` |
| 掛載點被真實資料夾或檔案佔用 | ✘ 被佔用 | 工具資料夾本來就有同名資料夾，或根目錄有真實的 `AGENTS.md` | apply 拒絕、不代為刪除。把內容搬進來源，或自己移除，再 apply |
| 孤兒連結 | ⚠ 設定已不再引用 | 先前 apply 建立、之後工具被移出 mount | apply 只回報；手動刪或 `agsy clean` |

## 六、merge 出狀況（Claude Code 的 settings.json）

`.claude/settings.json` 是你的檔案；agsy 只擁有 `hooks` 欄位裡「`statusMessage` 以 `agsy:` 開頭、或 command 指向 `.agsy/hooks/`」的群組。

| 情境 | status 顯示 | 處理 |
|------|------------|------|
| 你改了 agsy 寫的條目（例如 matcher 從 Bash 改成 Edit） | 清單 B：agsy 的條目被改過 | apply 詢問後整組重建。想保留：搬進你自己的群組（拿掉 `agsy:` 記號、command 不指向 `.agsy/`）或 `settings.local.json` |
| 你在 agsy 的群組裡加了自己的 handler | 同上 | 同上；agsy 的群組只放 agsy 的 handler |
| 你加了自己的群組、改了 permissions、model 等其他欄位 | 不算異常 | apply 與 clean 都不動 |
| agsy 的條目被刪，或整個檔案被刪 | ✘ 條目不見了 | `agsy apply` |
| 檔案不是 JSON 物件（壞掉、是陣列）或是符號連結 | ✘ 修好前 apply 拒絕 | 手動修；clean 會跳過並回報 |
| 來源裡沒有任何 hook | 沒有東西可合併 ✔ | 檔案不存在不建立；存在也不改寫 |
| `merge` 條目已從 `agsy.yaml` 移除 | ⚠ 孤兒：仍有 agsy 條目 | apply 不碰、持續回報；手動移除或 `agsy clean` |
| manifest 記錄的 merge 目標在專案外 | ⚠ 未檢查 | agsy 不開專案外的檔；自己打開並移除 `agsy:` 開頭的條目 |
| 專案搬移或 `build.out` 改名 | apply 之後同步 ✔ | 舊群組靠 `agsy:` 記號認出並取代 |

## 七、apply 在建置前就停下的條件

這些檢查排在捨棄確認之前：

| 條件 | 訊息大意 | 處理 |
|------|---------|------|
| 任一來源路徑不存在 | 拒絕以不完整的清單重建 | 修好路徑（clone、掛磁碟、改錯字） |
| 掛載點被真實路徑佔用 | 拒絕並列出 | 自己搬走或刪除 |
| workflow target 錯誤、`hook.yaml` 錯誤（解析失敗、未知事件、缺 command、`./` 加了引號、override 索引超出或清空 command、引用的腳本不存在） | 列出待修檔案 | 修 front matter 或 `hook.yaml`，或補 `build.tools` |
| merge 目標是符號連結或不是 JSON 物件 | 拒絕並列出 | 手動修 `.claude/settings.json` |
| 掛載點被真實的 `hooks.json` 佔用 | 拒絕並列出 | 把內容改寫成來源裡的 hook，再刪該檔 |
| 同名衝突（`on_conflict: error`） | 列出衝突組 | 改名或刪一份 |
| 最終輸出路徑碰撞（含跨類別） | 列出碰撞組 | 改名其中一個 |
| manifest 損壞但 `.agsy/` 存在 | 內容無從得知 | 多一次確認 |
| manifest 比本 agsy 新 | 無法解析 | 升級 agsy，或刪 `.agsy/` 重建 |

## 八、快速決策

```
 先跑 agsy status，然後：

 有產物端改動？
   ├─ 想留一些 ──▶ 逐筆搬進來源（指引會指名）──▶ agsy apply
   └─ 全部捨棄 ──▶ agsy apply（確認捨棄）

 只有來源異動或產物缺失？ ──▶ agsy apply

 掛載異常？
   ├─ 被真實路徑佔用 ──▶ 搬走它 ──▶ agsy apply
   ├─ 孤兒連結或孤兒 hook 條目 ──▶ 手動刪或 agsy clean
   └─ 其他（遺失、指錯、已斷）──▶ agsy apply

 來源路徑不存在？ ──▶ 先修路徑；修好前什麼都別跑
```
