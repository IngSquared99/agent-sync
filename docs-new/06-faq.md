## D-1. 觀念與日常使用

### Q1：我直接改了 `.claude/rules/` 裡的檔案，下次 apply 會不會被蓋掉？

`.claude/rules` 是指向 `.agsy/rules` 的連結，你改的其實是產物目錄裡的檔案。`apply` 重建前會偵測到這種「本機改動」，**先列出清單並問你要不要捨棄**，不會不吭聲就蓋掉。想保留改動：先跑 `agsy promote` 寫回來源，再 `apply`。

### Q2：`.agsy/` 要不要進版控？`agsy.yaml` 呢？

- `.agsy/` **不要**——它是隨時可重建的產物，`init` 時 agsy 也會主動問要不要幫你加進 `.gitignore`。
- `agsy.yaml` **要**——它是專案的同步設定，也是 `init` 編輯模式取代掉註解時的後悔藥。

### Q3：改了來源檔之後，各工具什麼時候會看到新內容？

跑完 `agsy apply` 之後。agsy 不是常駐程式、不會自動監看檔案——改完來源記得 apply（可以配 git hook：`agsy status` exit code 非 0 就提醒）。

### Q4：`plan`、`status`、`doctor` 有什麼差別？

- `doctor`：**環境**健檢——設定合法嗎、來源在嗎、連結建得起來嗎。
- `plan`：**這次建置**的完整預演——會收哪些檔、誰改名、誰被略過、連結會怎麼動。
- `status`：**現況與基準的落差**——來源改了沒重建？產物端被改了沒寫回？連結還健康嗎？

三個都是唯讀，隨便跑都安全。

### Q5：可以在專案的子目錄裡執行 agsy 嗎？

可以。除了 `init` 以外的指令都會像 git 一樣往上層尋找 `agsy.yaml`。`init` 刻意只看目前目錄——設定檔要建在哪由你站的位置決定，不會誤改到上層專案的設定。

### Q6：同一台機器多個專案可以共用一個來源庫嗎？

可以，這正是設計初衷。每個專案各有自己的 `agsy.yaml`，sources 都指向同一個 `~/all-ai-lib` 即可。注意：對共用庫 `promote` 寫回時會多一道確認，因為會影響所有用到它的專案。

## D-2. 我的檔案怎麼了

### Q7：為什麼我的 skill 沒有被收進去？

依收錄規則逐一檢查（`agsy doctor` 或 `agsy plan` 會直接告訴你原因）：

- skill 必須是**目錄**，不能是單一 `.md` 檔；
- 目錄裡必須有 `SKILL.md`（沒有的被視為素材或草稿）；
- 目錄內**不能包含任何符號連結**（安全考量，整個 skill 會被略過）；
- 名稱不能以 `.` 開頭。

### Q8：為什麼 rules 目錄裡的某個檔案沒被收？

rules / workflows 只收**單一 `.md` 檔**：目錄不收、副檔名不是 `.md` 不收、`.` 開頭不收、符號連結不收。原因都會列在 `plan` 的「排除清單」裡。

### Q9：status 說有 untracked 檔案，apply 還會把它刪掉，怎麼辦？

untracked＝有人（通常是 AI 工具）透過工具目錄在產物端**新增**了 manifest 不認識的檔案。它沒有對應的來源位置，所以 `promote` 寫不回去、`apply` 重建時會刪掉。**要保留：把檔案搬進某個來源的對應子目錄（如 `~/all-ai-lib/rules/`），再跑 `apply`。**

### Q10：檔名多了一段 `-fromlib-xxx` 是什麼？

那是同名衝突用 `rename` 策略時附加的**來源標籤**：`python-style.md` 同時存在於兩個來源時，會輸出成 `python-style-fromlib-all-ai-lib.md` 和 `python-style-fromlib-repo-ai-lib.md`，兩份都保留、看檔名就知道來自哪裡。skill 改名時 front-matter 的 name 也會同步改寫（promote 寫回時自動還原）。

### Q11：為什麼我的 workflow 沒出現在任何工具裡？

三種可能，`plan` 都會標出來：

1. front-matter 的 `target:` 寫到 `route.buckets` 沒有的值 → 路由錯誤，apply 直接拒絕；
2. 沒標 `target` 而 `route.default` 是空的 → 不會放進任何 bucket（有警告）；
3. 標的 bucket 沒有任何 mount 連結去讀（例如 bucket 有 `codex` 但你沒掛 `.codex`）。

### Q12：我不小心刪了 `.agsy/` 裡的東西（或整個 `.agsy/`）怎麼辦？

沒事。產物本來就是可重建的：`agsy apply` 跑一次全部回來。若 manifest 壞掉，apply 會多問一次確認（因為無法得知目錄裡有沒有你的改動）再重建。

## D-3. 衝突與寫回

### Q13：兩個來源有同名檔案會發生什麼事？

由該類別的 `on_conflict` 策略決定：`rename`＝兩份都留（附來源標籤）；`error`＝停下來列清單請你處理；`first`＝只留優先權高（sources 排前面）的那份。這是 `init` 的必答題，沒有隱含預設。

### Q14：為什麼 skills 建議用 `error` 而不是 `rename`？

skill 是靠描述語意觸發的，兩個同名 skill 並存時工具會選哪個難以預測；而且 rename 需要連 `SKILL.md` 的 name 一起改寫。同名 skill 通常代表真的該整併成一份，所以建議停下來人工處理。

### Q15：status 說「來源也改了」（兩邊都動），promote 拒絕寫回，怎麼辦？

這是保護：直接覆蓋會清掉來源端的新內容。請手動比對兩份（來源檔 vs `.agsy/` 裡的產物檔）、把要留的內容合併進**來源**，然後 `apply` 重建。重建後基準重設，一切恢復正常。

### Q16：我想把某個項目從共用庫搬到專案庫，怎麼做？

在產物端改好內容後：

```sh
agsy promote skills/code-review --to ./repo-ai-lib
```

注意 promote 完會提醒：**舊來源（共用庫）的那份還在**，下次建置會收到新舊兩份同名項目。確認新位置沒問題後，手動刪掉舊來源的那份。

### Q17：`promote --all` 和一個一個寫回有什麼差別？

`--all` 會先按來源分組列出全部項目（寫到專案外的共用庫會特別標警告），確認一次後逐項寫回；個別項目失敗（例如來源根目錄不見）不會中止整批，最後統一列出失敗清單。`--all` 不能配 `--to`。

## D-4. 平台與環境

### Q18：Windows 需要系統管理員權限或開發人員模式嗎？

不需要。Windows 上 agsy 用 **junction**（目錄重新解析點）而不是 symlink，一般使用者帳號就能建立。唯一注意：junction 存的是**絕對路徑**，把專案整個搬到別的位置後要重跑 `agsy apply` 重建連結（macOS / Linux 用相對 symlink，搬移不受影響）。

### Q19：換了一台電腦（或共用庫還沒 clone），status 冒出一堆警告？

若整個來源路徑不存在，status 會明確區分「**來源路徑不見**」和「來源檔被刪」：前者通常是共用 repo 還沒 clone、外接碟沒掛載、或路徑打錯。此時 `apply` 也會拒絕重建（避免把缺席來源的項目清掉）。把來源路徑補齊後再操作即可。

### Q20：可以在 CI 或 git hook 裡用嗎？

可以，設計上就有考慮：

- `agsy status`：exit `0`＝同步、`1`＝有落差，直接當檢查用；非 TTY 環境只印報告、不出互動選單。
- 需要執行動作的指令加 `--yes`（如 `agsy apply --yes`）；沒有 `--yes` 時非互動環境的確認一律**取消**，不會意外破壞東西。
- `agsy init --yes <sources...>`：非互動初始化。

### Q21：怎麼把介面切成中文／英文？

`export AGSY_LANG=zh-TW`（或任何 `zh` 開頭的值）＝繁體中文；`AGSY_LANG=en`＝英文。沒設 `AGSY_LANG` 時看 `LC_ALL` / `LANG`。

### Q22：如何完全移除 agsy？

1. 各專案跑 `agsy clean`（刪連結與 `.agsy/`；只刪 agsy 自己建的東西，真實檔案一律跳過並回報）。
2. 不需要的話刪掉 `agsy.yaml`。
3. 刪執行檔，依當初的安裝方式：`brew uninstall agsy`／`winget uninstall IngSquared99.agsy`／Go 安裝的刪 `~/go/bin/agsy`。

### Q23：status 說有「孤兒連結」（orphan）是什麼意思？

以前的 apply 建立過、但你後來把該工具從 mount 設定拿掉了的連結。工具還在透過它讀舊內容，所以 status 會一直提醒。`apply` 不會代刪（它只管目前設定內的連結）；請手動刪掉，或 `agsy clean` 一併清除。

### Q24：掛載點已經有一個真實的 `.claude/skills` 目錄（不是連結），agsy 說要我手動處理？

agsy **絕不刪除非它建立的真實目錄／檔案**。請把既有內容搬進某個來源（通常正是你想要的：讓它被 agsy 管理），或自行備份後刪除該目錄，再跑 `apply`。

### Q25：agsy 會不會把我來源裡的符號連結指到的檔案（例如私鑰）複製出去？

不會。掃描時符號連結一律不收（含 skill 目錄內部——含連結的 skill 整個略過），建置複製時還有第二道防線直接拒絕複製連結。這是刻意的安全設計：產物會被掛載給各工具讀，不能讓連結夾帶來源以外的檔案進去。
