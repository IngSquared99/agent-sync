# C-2. 指令說明

## C-2-1. 總覽

```
agsy                        互動選單（含狀態摘要）
agsy init [sources...]      產生 / 編輯 agsy.yaml
agsy doctor                 環境健檢（唯讀）
agsy plan                   預覽 build + mount 結果（唯讀）
agsy apply                  前置檢查 → 確認 → 清空重建 → 掛載
agsy status                 三方比對並報告落差（唯讀；exit 0=同步 1=有落差）
agsy promote [item] [--to <source>] [--all]
                            把產物側的改動寫回來源
agsy clean                  移除連結與產物（反安裝）
agsy version                版本資訊
agsy help                   說明文字
```

**全域旗標** `--yes` / `-y`：所有確認一律視為「是」。設計給 CI、腳本、git hook；沒有它時，非互動環境遇到需要確認的動作會**取消而非硬做**。

**通用行為**：

- 除了 `init`（只看目前目錄），所有指令都會從目前位置**往上層尋找** `agsy.yaml`（與 git 相同慣例），所以在專案子目錄裡也能直接執行。
- 介面語言依 `AGSY_LANG` / `LC_ALL` / `LANG` 自動切換（`zh*` → 繁體中文）。
- Windows 上用滑鼠雙擊執行時，結束前會暫停等你按鍵，視窗不會一閃而過。

各指令的建議節奏：

```
第一次        init → doctor → plan → apply
改了來源      (plan) → apply
改了掛載側    status → promote → apply
不確定狀態    status
要移除        clean
```

## C-2-2. `agsy`（互動選單）

不帶參數執行進入選單。行為：

- **找不到設定檔**：提示這是第一次使用，直接引導進 `init`。
- **有設定檔**：頂部先顯示一行狀態摘要（behind / new / local changes / untracked / missing outputs / mount issues 的數量），然後列出 apply / plan / promote / status / doctor / init / clean 選項。若偵測到本機改動，apply 選項旁會標註「需要先確認」。

適合不想背指令的使用者：所有功能都能從這裡進。

---

## C-2-3. `agsy init [sources...]`

產生（或編輯）`agsy.yaml`。細節：

### 全新建立

依序詢問：來源路徑（逐行輸入）→ 掛載哪些工具（多選，來自內建適配器）→ 三個類別的同名策略（必答；建議值 rules=rename、skills=error、workflows=rename）→ 產物目錄（預設 `.agsy`）→ 無 target 的 workflow 去向。寫檔後：

- 若有類別「會建置但沒有任何工具掛載」（例如只勾 Codex，rules/skills 就沒人讀），會提出警告。
- 詢問是否把產物目錄加進 `.gitignore`（已存在該條目就不會重複問）。

### 編輯模式（agsy.yaml 已存在）

- 每一題預先帶入目前值，**按 Enter 就是保留原值**。
- 已掛載的工具會預先勾選。
- **手動加過的東西不會被洗掉**：自訂 mount 項目、手動加的 bucket、改過的 `categories` 與 `route.field` 都原樣保留。
- 寫入前**顯示逐行 diff** 並要求確認；內容沒變就直接說「無變更」。
- 注意：yaml 內的註解會被範本註解取代（自訂註解要在寫入後自行補回）——設定檔進版控就是為了這種時刻。

### 非互動環境（CI / 腳本）

`init` 的核心是「策略必須由使用者明確選擇」，所以**沒有人能回答問題時預設是取消**。要在非互動環境使用：

```sh
agsy init --yes ~/all-ai-lib ./repo-ai-lib
```

來源用參數傳入，`--yes` 表示明確同意建議預設值（rules=rename、skills=error、workflows=rename）。

## C-2-4. `agsy doctor`

唯讀環境健檢，**不做任何動作**。檢查項目：

1. `agsy.yaml` 找得到、格式合法。
2. 每個來源路徑存在與否（不存在＝✘ 錯誤）。
3. 每個來源的各類別子目錄：缺少子目錄只是 ⚠ 提醒（不是錯誤）；存在的話統計會被收錄的檔數——**計數規則與 build 完全相同**，並逐一列出被略過的檔案與原因（例如「skill 目錄沒有 SKILL.md」「副檔名不是 .md」）。
4. 每個掛載點的現況：不存在（可直接建立）／已是連結／連結指錯或斷掉（apply 可修）／被真實目錄佔用（apply 會失敗，需手動處理）。
5. **連結能力實測**：實際建一個暫時連結再刪掉，不是只印宣稱。Windows 上驗證 junction 可用（不需特權）。

結尾統計 `N errors, M warnings`；有錯誤時 exit code 為 1。

**使用情境**：安裝後第一次驗證環境、「為什麼我的檔案沒被收進去」、換機器後檢查來源路徑。

## C-2-5. `agsy plan`

把 `apply` 會做的事完整演練一遍，**保證不寫入任何檔案**。輸出分三段：

### build 預覽

- 來源清單：優先權順序、存在與否、來源標籤（`tag: @all-ai-lib`）。路徑不存在的來源會標明「以下預覽不含此來源」。
- 每個類別：會收錄的項目、來自哪個來源、是否因同名被改名（附標籤）、workflow 分到哪些 bucket 及原因（「未標 target，套用預設」等）。
- 被 `first` 策略捨棄的項目、不符收錄規則被排除的檔案（附原因）。
- 擋路的問題：同名衝突（error 策略）、最終名稱撞名（collision）、workflow 路由錯誤——這些存在時 `apply` 會拒絕，`plan` 先一次列全。

### mount 預覽

每個連結的現況與將採取的動作：不存在（將建立）／已是連結（將刪除重建）／指錯或斷掉（將重建修復）／被真實目錄佔用（✘ apply 會失敗，請手動處理）。

### 摘要

一行統計：項目數 │ 改名數 │ 衝突數 │ 撞名數 │ 捨棄數（first）│ 排除數 │ 連結數 │ 掛載異常數。

exit code：有衝突／撞名／路由錯誤時為 1（可用於 CI 守門）。

**使用情境**：apply 前的例行確認、調整 `on_conflict` 或 `route` 後看效果、debug「某檔案為什麼沒進產物」。

## C-2-6. `agsy apply`

正式執行「清空重建＋掛載」。流程與所有中途停下的情況：

### 1. 前置檢查（全部通過才會走到確認）

| 檢查 | 不通過時 |
|------|----------|
| 所有來源路徑存在 | ✘ 拒絕：不從殘缺的來源清單重建（否則缺席來源的項目會被清掉） |
| 掛載點未被真實目錄／檔案佔用 | ✘ 拒絕並列出，請你手動搬走（agsy 絕不刪除非它建立的東西） |
| 無 workflow 路由錯誤 | ✘ 拒絕並列出待修檔案 |
| 無同名衝突（error 策略）／最終名稱撞名 | ✘ 拒絕；`plan` 可看完整清單 |

> 檢查刻意放在「確認捨棄改動」**之前**：不能讓你先同意丟掉本機改動、等建置跑完才發現這一輪注定失敗。

### 2. 確認本機改動（每次必查）

- manifest 可讀：逐項比對。發現**本機改動**（產物被改、還沒 promote）或 **untracked 檔案**（掛載側新增、重建會刪掉）就列出清單並詢問「捨棄並重建？」。
- 產物目錄存在但 manifest 壞掉／被刪：無法得知裡面有沒有你的改動，一律先問。
- 產物目錄不存在：第一次建置，不會蓋掉任何東西，直接進行。

### 3. 建置 → 掛載

清空產物目錄 → 依 plan 複製（skills 若改名會同步改寫 SKILL.md 的 name）→ 確保所有連結目標目錄存在（即使目前沒有任何 workflow，`workflows/<bucket>/` 也會建立空目錄，連結才不會斷）→ 寫入 manifest → 建立連結。

若掛載階段失敗（例如檔案系統不支援連結）：**建置成果完好保留**，訊息會告訴你修好問題後重跑 `agsy apply` 即可，只有掛載步驟未完成。

### 4. 孤兒連結回報

`apply` 會記錄本次建立的連結。若之前的 apply 建過、但目前設定已不再引用的連結（例如你從 mount 拿掉了某個工具），會列出提醒——**apply 只回報不刪除**；要移除請手動刪或跑 `agsy clean`。

## C-2-7. `agsy status`

三方比對（來源 ↔ manifest ↔ 產物/掛載），輸出完整報告。本體永遠唯讀。

### 報告結構

**① sources → 產物方向（apply 負責的方向）**

- `behind`：來源更新了、產物還沒重建。特別標註兩種次狀態：
  - 「來源檔已刪除 ⚠」（apply 後該項目會消失）；
  - 「來源路徑整個不見 ⚠」（共用庫沒 clone？外接碟沒掛？——是路徑不見，不是檔案被刪，**先修路徑再說，別急著 apply**）。
- `new`：來源有新檔案，還沒進產物。
- `missing artifacts`：產物側的複本被刪了（掛載側讀不到；apply 可重建）。

**② 產物 → sources 方向（promote 負責的方向）**

- `local changes`：產物被改了（與建置當下不同），可寫回。可能附加：
  - ⚠ 來源也同時改了（寫回需人工比對）；
  - ⚠ 多個 bucket 複本被改成不同內容；
  - ⚠ 來源檔已刪除（promote 會重建它）；
  - ⚠ 來源根目錄不見（promote 會拒絕）。
- `untracked`：掛載側新增、manifest 不認識的檔案。**promote 寫不回去（沒有原始位置）、apply 會刪掉**——要保留就搬進某個來源目錄再 apply。

**③ mounts**

每個掛載目錄的連結狀態：正常 ✔／連結不見（可能被手動刪除，重跑 apply 修復）／指錯或斷掉／被真實目錄佔用（手動處理）／孤兒連結（apply 不會移除，手動刪或 `clean`）。

**④ summary 與建議**

一行統計加上下一步建議（例如「先 promote 保住改動，再 apply 重建」）。

### exit code 與行動選單

- `0`＝完全同步；`1`＝有任何落差。適合放 CI / git hook。
- 在終端機互動執行且有落差時，結尾會出現行動選單（直接跳轉 promote / apply）；非 TTY（CI）只印報告。

## C-2-8. `agsy promote`

把產物側（＝掛載側，工具實際讀寫的位置）的改動**寫回來源**。四種用法：

```sh
agsy promote                          # 互動：多選要寫回的項目，每項可改寫回目標
agsy promote skills/code-review       # 單一項目（用「類別/名稱」全名）
agsy promote code-review              # 也可只給名稱；若多類別撞名會列出全名請你重下
agsy promote skills/code-review --to ./repo-ai-lib   # 單一項目，改寫回到指定來源
agsy promote --all                    # 全部寫回各自的原始來源（先列清單再確認）
```

- `--to` 只能指向 **agsy.yaml 已設定的來源**（寫到別處等於脫離管理）。
- `--all --to` 不支援（整批改道會讓來源與 manifest 脫鉤）。

### 保護規則（逐項判斷，單項失敗不會中止整批）

| 狀況 | promote 的行為 |
|------|----------------|
| 來源**也**被改了（兩邊都動） | ✘ 拒絕——直接覆蓋會清掉來源的新內容，請人工比對合併 |
| 多個 bucket 複本改成**不同**內容 | ✘ 拒絕——要由人決定哪份是對的（改成相同內容則視為一份改動，正常寫回） |
| 來源檔已被刪除 | ⚠ 明確詢問「要重建它嗎？」才寫 |
| 來源根目錄整個不見 | ✘ 拒絕——先修好來源路徑 |
| 寫回目標在專案外（共用庫） | ⚠ 額外確認——會影響所有用到這個庫的專案 |

### 寫回後自動做的事

- 被改名過的 skill：寫回時自動把 `SKILL.md` 的 `name` **還原成原始名稱**（`-fromlib-…` 是只存在於產物的名字，不能洩漏回來源）。
- workflow 有多個 bucket 複本時：寫回的內容同步到其他複本，保持一致。
- 更新 manifest 的基準雜湊：status 不會再對同一份改動嘮叨；但「來源已更新」（behind）會開始顯示，提醒你接著跑 `apply`。
- 用 `--to` 改道時會提醒：**舊來源的檔案還在**，下次建置會同時收到新舊兩份同名項目——確認新位置沒問題後請手動刪掉舊的。

## C-2-9. `agsy clean`

反安裝：移除掛載連結與整個產物目錄，**`agsy.yaml` 保留**。行為：

- 執行前先確認。
- 只刪 agsy 建立的東西：掛載點若是**真實目錄／檔案**（非本工具建立）一律跳過並回報。
- 連同 manifest 裡記錄的**孤兒連結**一起清（但每條路徑都先驗證「確實是指向產物目錄的連結」才動手——manifest 內容不被無條件信任）。
- 連結刪除後若掛載目錄變成空目錄，也一併移除（那個空目錄同樣是 agsy 建的）。
- 最後刪除產物目錄（同樣經過危險路徑防呆）。

之後想恢復，跑一次 `agsy apply` 即可全部重建。
